## Why

0.1.2 在持仓中存在无行情标的时会把后端省略的 `quote` 当作有效对象，异步数据返回后触发未捕获异常并导致安装版整页黑屏。同时，当前全市场调度只刷新管理员选中的单一来源，普通用户无法在已缓存来源间自主选择，单股模式的实际客户端轮询频率也与后台配置混在一起，难以理解和控制。

## What Changes

- 修复 `quote` 缺失时的首页运行时异常，并增加应用级错误边界，使单个组件异常不再导致整页黑屏。
- 在全市场模式的交易时段并行刷新新浪和东方财富快照，分别写入永久 Redis 缓存；任一来源失败不影响另一来源及其最后成功快照。
- 将全市场来源选择改为每台客户端的普通用户偏好；选择只决定该客户端读取哪个缓存，不修改全局后台配置。
- 将“全市场快照 / 单只股票”工作模式改为每台客户端的普通用户偏好；服务端全市场双源调度不再因默认模式为单股而停止。
- 保留管理员对服务端全市场快照刷新频率的控制，并让同一频率作用于两个并行来源。
- 全市场模式在首页明确显示“服务端快照刷新频率”。
- 单股模式在首页明确显示“客户端查询频率”，支持每台客户端选择 2、5、10、20 秒，默认 10 秒，并让主界面与透明小窗采用该轮询频率。
- 将单股上游来源也改为每台客户端的普通用户偏好，允许在东方财富和雪球之间自由切换；后续单股请求按用户所选来源实时查询，管理员配置仅作为未保存偏好时的默认值。
- 优化主窗口布局，使工作台、行情设置和管理页都被约束在当前窗口可视区内；禁止整页上下滚动，长列表只在内容卡片内部滚动。
- 将桌面应用版本升级为 0.1.3，并补充安装版登录、部分行情缺失、双源并行和动态轮询验证。

## Capabilities

### New Capabilities

- `dashboard-render-resilience`: 约束部分行情缺失和组件异常时首页仍可渲染、提示并恢复，禁止整页黑屏。
- `dual-market-snapshot-refresh`: 约束新浪与东方财富快照并行、隔离、永久缓存和管理员刷新频率。
- `client-market-refresh-preferences`: 约束普通用户的全市场读取来源和单股客户端查询频率选择、展示与轮询行为。
- `viewport-contained-layout`: 约束主窗口各页面自适应当前尺寸、整页不产生纵向滚动以及长列表内部滚动。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无已归档基线，本变更以新能力规范描述 0.1.3 的增量行为。

## Impact

- Spring API：行情请求上下文、持仓/行情接口、双源调度、Redis 分源锁、配置与状态接口。
- AKShare 网关：继续复用现有新浪、东方财富接口和分源健康统计，不增加新的外部依赖。
- 桌面端：Dashboard、透明小窗、行情配置页、管理页、React Query 动态轮询、本地偏好存储、可视区布局、错误边界和版本号。
- Redis：保留 `snapshot:sina` 与 `snapshot:eastmoney` 两个永久 Hash，刷新锁改为按来源隔离。
- 权限：普通用户可以选择自己的工作模式、全市场读取来源、单股上游来源和轮询频率；只有管理员可以修改服务端快照刷新频率及客户端未设置时采用的默认模式和默认来源。
- 发布：需要本地 PostgreSQL/Redis/AKShare 完整验证、macOS 安装版登录复现测试、云端发布以及 0.1.3 双平台安装包。
