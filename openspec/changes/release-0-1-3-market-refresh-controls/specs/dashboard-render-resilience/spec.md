## ADDED Requirements

### Requirement: 部分行情缺失时首页保持可用
系统 MUST 将持仓响应中为 `null` 或被省略的行情字段视为无行情，并继续渲染其余持仓、可用行情和页面操作，禁止因读取缺失行情属性而出现整页黑屏。

#### Scenario: 响应省略一个持仓的行情字段
- **WHEN** 持仓接口返回多个标的，至少一个包含行情且至少一个省略 `quote` 字段
- **THEN** 首页显示可用行情和全部可展示的持仓信息，并且不抛出未捕获渲染异常

#### Scenario: 所有持仓均无行情
- **WHEN** 持仓接口中的所有项目均不包含有效行情
- **THEN** 首页显示无行情或占位状态，并且导航与添加自选等操作仍然可用

### Requirement: 未预期渲染异常可见且可恢复
桌面应用 MUST 在根渲染树提供错误边界；当未预期的组件异常发生时，系统 MUST 显示可理解的错误提示和重新加载入口，而不是显示纯黑或纯空窗口。

#### Scenario: 子组件渲染异常
- **WHEN** 登录后的任一子组件抛出未捕获渲染异常
- **THEN** 应用显示恢复界面，并允许用户触发重新加载

### Requirement: 安装版黑屏回归验证
0.1.3 macOS 安装版 MUST 使用包含部分缺失行情的真实响应形态完成登录冒烟验证。

#### Scenario: 安装应用登录并等待异步数据
- **WHEN** 用户在已安装的 0.1.3 应用登录并等待持仓异步请求完成
- **THEN** 首页在响应前后均保持可见，且至少持续观察一个客户端查询周期不出现黑屏
