## Context

生产故障表明 Spring API 与 Redis 实际可用，但管理员切换到不可用的东财全市场源后，Redis 中只有新浪快照且带 24 小时 TTL，行情查询返回 503，桌面端统一显示成“无法连接 API”。同时，加自选的搜索可能触发昂贵的全市场读取或 AKShare 请求，保存持仓还在数据库事务中同步查询实时行情；任一上游超时都会让用户感觉界面卡死。

系统现有边界为 React/Tauri 桌面端、Spring Boot API、Python AKShare 网关、PostgreSQL 与 Redis。AKShare 是非商业研究数据源，当前改造需继续禁止 DEMO 回退，并为以后替换授权行情源保留 Provider 边界。

## Goals / Non-Goals

**Goals:**

- 行情上游失败、非交易时段和应用重启后都能读取 Redis 中最后一次成功的真实行情。
- 证券搜索、加自选和持仓保存不依赖实时行情链路。
- 每日自动维护可查询的 A 股代码与名称目录。
- 单只证券行情缺失时隔离故障，让首页其他自选项继续展示。
- 数量、成本和搜索交互可预测，并对超时、失败和重复提交给出明确反馈。

**Non-Goals:**

- 本次不实现交易所法定节假日日历，调度仍以北京时间工作日和既定交易时间窗判断。
- 本次不实现证券退市历史、复权、分红送转或行情数据仓库。
- 本次不让桌面端直接访问 AKShare，也不改变 AKShare 的研究用途合规边界。
- 本次不接入新的商业行情 Provider。

## Decisions

### 1. Redis 保存“最后成功快照”，不设置 TTL

每个 Provider/模式/源继续使用独立 Redis Hash。一次抓取只有在响应非空且全部标准化成功后才进入写阶段；Lua 先把当前 Hash 的全部字段复制到唯一临时 Hash，再以 `HSET` 覆盖本次成功返回的证券并写入同一 Hash 内的保留元数据字段，最后以唯一的 `RENAME` 命令切换正式 Key。`RENAME` 前的异常只会留下可删除的临时 Key，不能污染当前快照；本次未出现的旧证券继续保留，正式 Key 不设置过期时间。

备选方案是直接在正式 Hash 上逐字段 `HSET`，但 Lua 运行时错误不会回滚已完成命令，可能造成部分更新，因此不采用。启动时遍历全部快照源，移除旧版本 TTL；若旧元数据已丢失但行情 Hash 尚存，则从有效行情的 `sourceTimestamp` 重建元数据。

### 2. 交易时段刷新，查询始终读取最后快照

调度器仅在北京时间工作日 `09:15-11:30`、`13:00-15:00` 按管理员频率调用全市场接口；其他时段不访问上游。查询不以当前是否交易为拒绝条件，始终返回最后快照，并根据当前市场时段和快照抓取时间计算 `marketPhase`、`stale` 与状态说明，避免把收盘数据误标为盘中实时。

### 3. PostgreSQL 成为证券目录事实来源

新增 `securities` 表，以规范化 `instrument_id` 为主键，并保存交易所、代码、名称、来源及同步时间。AKShare 网关新增代码名称目录接口，Spring 在每天北京时间 08:00 拉取、完整校验后批量 upsert；空响应或异常不删除已有行。服务启动时若目录为空，异步补同步一次，避免首次部署必须等到次日。

目录仅约数千行，使用规范代码精确/前缀检索与名称包含检索即可，暂不引入 `pg_trgm` 扩展。同步用 Redis 短锁避免多实例重复执行，但证券业务数据本身只存 PostgreSQL。

### 4. 写入持仓与行情读取解耦

新增自选时，API 只从 PostgreSQL 校验证券并保存用户数据，事务内不调用行情服务。持仓列表再批量查询行情；对缺失或失败的证券返回 `quote=null`、不可计算的市值/盈亏为 `null` 及缺失计数，而不是把未知值伪装成零或让整个请求失败。已有最后行情可继续用于展示，但必须标注陈旧状态。

备选方案是后台任务在保存后立即预热行情，但全市场快照模式下没有必要，且会增加队列与一致性复杂度。

### 5. 前端使用字符串草稿与可取消请求

数量和成本在编辑阶段保存为字符串，允许 `""`、`"1."`、`"0.25"` 等中间态；提交时统一解析和校验。未持仓自选允许数量为 0 且成本为空，正持仓必须提供正成本。打开表单时字段为空，不以数值 0 占位。

证券搜索为空时不请求；非空请求防抖并使用 `AbortController`/请求序号丢弃旧响应。提交后禁用按钮，所有请求设置客户端超时，并分别展示服务不可达、行情不可用和正在使用最后快照。

首页以每条 `Quote.sourceTimestamp` 作为股票最后刷新时间；`receivedAt` 只代表系统接收时间，不用于向用户宣称行情已刷新。无行情时显示“暂无行情时间”，陈旧或非交易时段继续显示最后真实时间。

## Risks / Trade-offs

- [Redis 无 TTL 会积累已退市证券字段] → 当前规模有限；证券目录控制新增与搜索，后续可增加管理员离线清理任务而不影响最后快照语义。
- [工作日判断会在法定节假日请求上游] → 上游失败不覆盖缓存；后续接入交易日历时只替换时段判断组件。
- [08:00 同步时 AKShare 不可用] → 保留旧目录、记录失败日志和指标，并允许管理员或运维触发补同步。
- [数据库目录首次为空] → 启动后异步同步；同步完成前搜索返回明确的“证券目录准备中”，不退回实时行情搜索。
- [部分行情降级增加客户端状态复杂度] → 统一可空行情 DTO 和状态码，前端集中渲染状态，不在各组件自行猜测异常原因。

## Migration Plan

1. 先发布 AKShare 网关目录接口并验证返回非空、代码格式正确。
2. 发布数据库迁移与 Spring API；启动后填充证券目录，并确认 Redis 快照键已取消 TTL。
3. 观察一次交易时段刷新与一次非交易时段查询，确认最后快照保留且无 DEMO 数据。
4. 发布 Web 与桌面端，验证搜索、加自选、持仓列表部分降级和数值输入。
5. 回滚应用时保留新增表与 Redis 数据；旧版本可忽略新表。若回滚到仍设置 TTL 的版本，需立即恢复新版或由运维移除快照 TTL，避免最后数据再次过期。
