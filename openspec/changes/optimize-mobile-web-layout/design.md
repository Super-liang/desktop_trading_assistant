## Context

前端目前以 900px 为桌面/移动端主断点，但移动端底部导航仍按三列承载五到六个入口，实际形成两行并依赖固定的 116px 内容补偿。持仓列表沿用了桌面端 `flex: 1` 的填充策略，手机上会产生大块空白；多个横向区域虽可滚动，但缺少稳定的边缘留白和滚动定位。弹窗已有 `100dvh` 限制，但底部导航仍在遮罩层之上可见，短屏时表单密度也偏高。

## Goals / Non-Goals

**Goals:**

- 在 320px 以上手机宽度维持单行、可触控的主导航。
- 确保页面和弹窗不被底部导航或安全区遮挡，不产生页面级横向滚动。
- 提高首页、持仓页、行情源页在 390×844 和 375×667 视口中的信息密度与可读性。
- 通过语义化组件测试和真实手机视口截图验证关键流程。

**Non-Goals:**

- 不重新设计桌面端侧边栏、桌面透明小窗或后台管理信息架构。
- 不修改行情、收益、持仓 API 和数据模型。
- 不追求所有内容单屏展示；手机端允许自然纵向滚动，但关键操作不能被固定区域遮挡。

## Decisions

1. **底部导航采用“三个主入口 + 更多”四等分结构。** 首页、我的持仓、实时行情源保留为主入口；修改密码、管理员入口和退出登录放入移动端“更多”操作面板。相比强行压缩五到六个入口，四列在 320px 宽度仍能维持至少约 44px 的触控区域和可读标签。
2. **使用统一 CSS 变量表示移动导航高度。** `--mobile-nav-height` 同时用于应用壳底部留白、页面最小高度和行情源保存栏定位，消除多个硬编码 `116px`。安全区通过 `env(safe-area-inset-bottom)` 叠加。
3. **移动端列表取消桌面填充高度。** 持仓页的 `list-card` 在移动断点使用内容驱动高度，空状态设置紧凑但可读的最小高度；桌面端继续保持填满窗口的高密度列表。
4. **横向内容采用显式滚动容器。** 市场标签和指数卡片使用 `overflow-x:auto`、滚动吸附、左右内边距及可见的下一项边缘提示，不压缩文字，也不触发页面级横向滚动。
5. **弹窗提升到移动导航之上并使用内部滚动。** 提高遮罩层层级，遮住底部导航；短屏断点减小标题、字段间距和内边距，同时保留输入框/按钮至少 44px 的触控高度。
6. **移动优化以 CSS 为主，仅导航信息架构引入少量 React 状态。** 避免复制手机专属页面；“更多”面板作为轻量语义化对话区域，支持关闭、导航和账号操作。

## Risks / Trade-offs

- [更多面板增加一次点击才能修改密码或退出] → 这些属于低频操作，换取核心导航稳定单行；面板提供清晰标签和大触控区域。
- [移动媒体查询可能影响窄窗口桌面壳] → 继续以 900px 为断点，并在常用桌面窗口尺寸执行回归测试。
- [固定底栏与手机浏览器动态工具栏叠加] → 使用 `dvh` 和安全区变量，不依赖静态 `vh`。
- [横向滚动入口不易被发现] → 保留下一项部分可见并使用滚动吸附，市场标签同时支持触控拖动。

## Migration Plan

1. 先补充导航和关键结构测试，再调整组件与响应式 CSS。
2. 使用本地网页版分别验证 390×844、375×667 和桌面视口。
3. 验证通过后仅发布静态网页资源；后端无需迁移或重启。
4. 如出现回归，可回滚前端发布目录，不涉及数据库回滚。

## Open Questions

无。首期以常见 iPhone 宽屏与短屏尺寸作为验收基线，Android 浏览器使用相同 CSS 约束。
