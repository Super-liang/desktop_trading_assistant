## Why

0.1.5 的行情调度、证券目录和持仓收益均以 A 股为中心，无法正确处理港股、美股的时区、节假日、币种和基金净值披露节奏；现有年化收益又缺少足够历史行情支撑。0.1.6 需要先建立跨市场日历、证券主数据和可解释收益基线，才能安全扩展多市场持仓而不产生错误刷新或误导性收益。

## What Changes

- 接入 A 股、港股和美股交易日历，按各市场时区、午间休市、节假日及美股提前收市计算 `PRE_OPEN`、`OPEN`、`BREAK`、`CLOSED`、`HOLIDAY` 状态；交易日历落库并记录来源、同步时间和覆盖范围。
- 将行情刷新、证券目录刷新和页面交易状态统一建立在交易日历之上；A/H/美证券目录在各自下一交易日开盘前一小时同步，基金目录和前一净值在北京时间 07:00 同步。
- 扩展证券主数据与持仓模型，支持 `A_SHARE`、`HK_STOCK`、`US_STOCK`、`PUBLIC_FUND`，记录市场、交易所、币种、资产类型和建仓日期；既有持仓平滑迁移为 A 股且保持原证券标识兼容。
- 将“我的持仓”拆分为 A 股、港股、美股、公募基金四个始终可见的子菜单；没有持仓的市场展示独立空状态。添加持仓时先选市场，再搜索对应证券，并输入数量、成本和建仓日期。
- 通过 AKShare 接入沪深京 A 股、港股和美股全市场行情，以及开放式公募基金目录与单位净值；缓存按市场、来源和证券隔离，失败时保留最后成功数据并明确延迟/过期状态。
- 首页只展示上证指数、深证成指、创业板指、北证 50、科创综指、科创 50、沪深 300 七个大盘指数，不展示个股；指数卡横向滑动，默认首屏为上证指数、深证成指、创业板指。首页持仓和收益按市场、原币种分组，0.1.6 不在缺少外汇基准时跨币种求和。
- 将首页所有服务/上游指示灯收纳到右上角“联通检测”折叠面板，保留异常摘要和无障碍状态提示。
- 新增每日开盘基线，保存开盘价和开盘持仓数量；日收益按 `开盘持仓数量 × (当前价 - 当日开盘价)` 计算，当日新建或修改的持仓从下一交易日进入标准日收益统计。
- 删除产品界面的年度/年化收益，新增持有收益与持有收益率，按成本和当前价计算；旧年度字段在 0.1.6 API 中保留为弃用兼容字段且不再作为产品指标展示。
- 公募基金首期仅支持开放式基金单位净值，不支持货币基金万份收益、累计净值口径或封闭式基金；不按股票实时轮询，07:00 获取最新已披露单位净值和前一单位净值，以净值日期展示数据新鲜度并计算净值日收益与持有收益。

## Capabilities

### New Capabilities

- `multi-market-trading-calendar`: 三地交易日历、市场时区、交易阶段、提前收市和日历同步/降级规则。
- `multi-market-instrument-catalog`: A/H/美股票与公募基金主数据、规范证券标识、按市场搜索和开盘前目录同步。
- `multi-asset-portfolio`: 多市场持仓、建仓日期、分市场页面与旧 A 股持仓迁移兼容。
- `multi-market-quote-routing`: A/H/美实时或延迟行情、基金日净值、来源能力矩阵、缓存隔离和失败回退。
- `portfolio-return-baselines`: 开盘价/开盘数量基线、日收益、持有收益、基金净值收益和跨币种展示口径。
- `dashboard-market-overview`: 沪深京指数概览、各市场交易状态和可折叠联通检测面板。

### Modified Capabilities

无。仓库尚未归档基线 specs，本次以完整新能力规范记录 0.1.6 行为。

## Impact

- 数据库新增市场日历、跨市场证券主数据、持仓市场/币种/建仓日期和每日收益基线；Flyway 迁移必须兼容既有 A 股数据且不得删除历史收益表。
- Spring API 的证券搜索、持仓、行情、收益和状态 DTO 扩展市场、币种、交易阶段、净值日期及数据新鲜度字段。
- AKShare 网关新增港股、美股、基金和指数适配器，并需要升级固定 AKShare 版本、增加交易日历依赖与契约测试。
- 桌面端新增市场选择、四类持仓子菜单、首页指数概览和折叠联通检测；移除年度/年化展示。
- 调度器从固定北京时间判断改为以市场日历驱动；Redis key 必须包含市场与来源，避免跨市场数据污染。
- 生产部署需要先备份 PostgreSQL，再执行向前兼容迁移；行情仍仅用于非商业研究验证，港股东财数据约有 15 分钟延迟，不能宣传为交易所级实时行情。
