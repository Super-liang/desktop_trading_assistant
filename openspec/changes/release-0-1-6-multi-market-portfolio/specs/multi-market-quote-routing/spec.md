## ADDED Requirements

### Requirement: 行情来源按市场和能力配置
系统 SHALL 以 `market + capability + source` 表示行情配置，并 SHALL 只向管理员和普通用户展示当前市场真实支持的来源选项。

#### Scenario: 港股只有一个可用来源
- **WHEN** 0.1.6 港股能力矩阵只启用东方财富
- **THEN** 配置页面不显示无实现的新浪或 A 股单股来源

#### Scenario: 普通用户选择美股来源
- **WHEN** 美股存在多个已启用来源且普通用户切换来源
- **THEN** 仅该用户/设备的读取来源改变，管理员服务端刷新频率不被修改

### Requirement: A 股沪深京全市场行情完整接入
AKShare 网关 SHALL 使用沪深京全市场接口接收 SSE、SZSE 和 BSE 上市公司，并 SHALL 在来源失败时保留对应来源最后成功快照。

#### Scenario: 北交所股票进入快照
- **WHEN** `stock_zh_a_spot_em` 返回合法北交所代码
- **THEN** 网关规范化为 `BSE` 证券且 Spring API 可供持仓读取

#### Scenario: 新浪调用频率受限
- **WHEN** 新浪全市场接口因限流失败
- **THEN** 系统只标记新浪来源故障并保留其最后快照，不污染东方财富来源

### Requirement: 港股和美股使用服务端共享快照
系统 SHALL 在各自常规交易阶段刷新港股和美股全市场快照，用户持仓从共享 Redis 快照读取，不 SHALL 让每个客户端逐股直连 AKShare。

#### Scenario: 港股延迟行情
- **WHEN** 港股东方财富快照成功
- **THEN** 响应包含 HKD、行情时间、来源和约 15 分钟延迟提示

#### Scenario: 美股常规时段
- **WHEN** 美股处于盘前或盘后而非常规交易阶段
- **THEN** 系统不主动抓取扩展时段行情并继续展示最后常规行情

### Requirement: 公募基金按净值日期提供行情
系统 SHALL 只为开放式基金返回最新单位净值、前一单位净值、净值日期、前一净值日期、来源和数据状态，不 SHALL 使用股票的实时市场阶段描述基金，也不 SHALL 将货币基金万份收益、累计净值或封闭式基金混入首期单位净值模型。

#### Scenario: 非首期基金类型
- **WHEN** Provider 返回货币基金、封闭式基金或仅有非单位净值口径的数据
- **THEN** 系统不将该记录加入 0.1.6 公募基金可选目录和行情缓存

#### Scenario: 基金最新净值可用
- **WHEN** 07:00 同步获得新的单位净值
- **THEN** 持仓读取返回新净值并只覆盖相同基金对应的缓存记录

#### Scenario: 基金上游失败
- **WHEN** 基金目录或净值接口失败
- **THEN** 系统返回最后成功净值及过期标志，不清空用户基金持仓展示

### Requirement: Redis 行情缓存按市场来源隔离且不主动失效
Redis key MUST 包含市场、能力和来源；成功刷新 SHALL 只更新对应命名空间，业务行情 SHALL 不设置主动过期时间。

#### Scenario: 港股失败不影响美股
- **WHEN** 港股快照刷新失败而美股刷新成功
- **THEN** 港股保留旧值，美股更新为新值，二者健康状态独立

#### Scenario: 服务重启后读取最后行情
- **WHEN** API 或 AKShare 网关重启且上游暂不可用
- **THEN** 系统仍能从 Redis 读取此前成功保存的对应市场行情
