## Context

私有源码仓库已经发布 v0.1.3 双平台安装包，但私有可见性使外部用户无法访问。公开整个源码仓库会同时暴露实现、部署拓扑和历史资料，超出用户要求。最小公开面应是一个新仓库：默认分支只有产品 README，二进制通过 GitHub Release 承载。

## Goals / Non-Goals

**Goals:**

- 提供无需源码仓库权限即可访问的产品介绍和安装包下载页。
- 确保公开 Git 历史不包含任何业务源码、配置文件、OpenSpec、部署脚本或构建缓存。
- 保持 macOS/Windows 资产名称和 SHA-256 与已验证的私有 v0.1.3 Release 一致。
- 明确未公证/未商业签名、AKShare 研究用途和非投资建议。

**Non-Goals:**

- 不公开源代码或开发文档。
- 不开放 Issue、Discussion 或 Pages 等额外产品运营能力。
- 不重新构建安装包，不修改安装包内嵌 API。
- 不删除或改变原私有仓库与 Release。

## Decisions

### 1. 新建独立公开仓库而不是修改现有仓库可见性

公开仓库使用 `stock-trading-assistant-releases`，名称直接表达其二进制分发用途。相比把私有仓库转为公开，新仓库能从根本上隔离历史提交、源码和部署信息。

### 2. Git 默认分支只包含 README

在独立临时目录初始化全新 Git 历史，仅写入 `README.md`。安装包不提交到 Git，大文件全部放在 GitHub Release，避免仓库体积膨胀和二进制历史污染。

### 3. 从既有私有 Release 重新下载并校验资产

通过已认证的 GitHub CLI 下载 v0.1.3 的五个资产到临时目录，使用两个 SHA-256 清单验证 DMG、APP ZIP 和 NSIS EXE。验证后上传到新公开仓库同名 v0.1.3 Release。

### 4. 使用公开专用 README

README 只保留产品定位、功能、行情模式、平台下载、安装提示、隐私与合规边界。删除源码克隆、本地启动、服务器端口、私有文档相对链接和内部工作流说明。

## Risks / Trade-offs

- [公开二进制会扩大未经授权传播范围] → README 明确版本、哈希、签名状态、数据源限制和非投资建议。
- [误把私有文件提交到公开仓库] → 使用新的空目录和全新 Git 历史，提交前执行允许列表检查，根目录必须且只能有 `.git` 与 `README.md`。
- [安装包资产在复制过程中损坏] → 上传前后分别下载并校验 SHA-256，Release 必须且只能有五个预期资产。
- [公开仓库名需要调整] → 当前采用用户未指定名称时的明确默认值；仓库创建后可由 GitHub 重命名并保留重定向。
