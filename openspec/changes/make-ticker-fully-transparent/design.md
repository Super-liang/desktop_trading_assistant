## Context

原生 `ticker` 窗口已设置 `transparent: true`，但全局 `:root/body` 与 `.ticker-window/header` 仍绘制深色背景、模糊、边框和阴影，因此操作系统透明能力被前端覆盖。透明度偏好属于非敏感本机显示配置。

## Goals / Non-Goals

**Goals:**

- 从 HTML 根节点到行情容器的整条绘制链保持透明。
- 保留可读的行情文字、拖动区域、隐藏操作和文字透明度调节。
- 文字透明度在 20%–100% 之间以 10% 步长调节，并跨重启记忆。
- 不破坏主窗现有深色主题。

**Non-Goals:**

- 本次不提供窗口背景色或毛玻璃强度调节。
- 不修改全局个性化、主题、行情接口或云端用户设置。

## Decisions

1. 在 React 挂载前根据 `?view=ticker` 给 `html/body` 增加专用 class。相比只修改 `.ticker-window`，该方式可覆盖全局 `:root/body/#root` 的黑色底色，并避免首帧黑色闪烁。
2. 小窗容器、标题区、表格行全部取消背景、边框、阴影和 `backdrop-filter`，仅使用文字颜色与轻量文字阴影维持不同壁纸上的可读性。
3. 使用文字按钮 `− / 百分比 / + / 隐藏`，避免新增实色控制面板。透明度通过 CSS 自定义属性应用于小窗文本层。
4. 显示偏好使用带范围校验的 `localStorage` 保存；其中不含令牌、持仓或其他敏感信息。

## Risks / Trade-offs

- [浅色或复杂壁纸降低可读性] → 保留轻量文字阴影，并允许用户把文字透明度提高到 100%。
- [透明度过低难以找到控制项] → 下限限制为 20%，鼠标悬停标题区时控制文字恢复到可操作强度。
- [全局样式误伤主窗] → 所有覆盖样式限定在 `ticker-surface` 与 `.ticker-window` 命名空间。
