## Context

当前后端已有 `users.last_login_at`，且密码登录会更新该字段；管理员列表 DTO 也已返回它，但管理界面尚未展示。当前持仓仅保存最新数量与成本，没有交易流水、现金流或每日净值，因此现有 `totalProfit` 只是按成本计算的累计未实现盈亏，不能直接作为日收益或严谨的历史年化业绩。现有 `admin_audits` 只适合记录管理员动作，不能表达普通用户持仓操作。

桌面端当前由 `Dashboard` 同时承担导航、行情轮询、透明小窗广播、首页和持仓操作。窄屏时侧栏被隐藏且没有替代导航，根节点又禁止滚动，手机浏览器无法访问完整功能。单股 AKShare 行情只在网关进程内短暂缓存，上游抖动超过数秒后会返回空数据。

本版本同时涉及 API、数据库、定时结算、Redis、AKShare 网关、React 页面结构和 Tauri/Web 图标，必须保证管理端隐私裁剪发生在服务端，并保证现有透明小窗持续收到行情。

## Goals / Non-Goals

**Goals:**

- 为本人和管理员提供口径明确、带数据状态的日收益、本年收益和年化收益率。
- 管理员按用户查看最后登录、持仓证券清单、聚合收益和关键操作审计，不暴露数量与成本。
- 建立可供未来排行榜演进的每日收益聚合和不可变操作审计基础。
- 将首页和持仓页分离，新增安全改密能力，并完整适配手机浏览器。
- 单股行情上游失败时持续展示各来源最后一次成功数据。
- 桌面和 Web 使用统一的新品牌图标。

**Non-Goals:**

- 0.1.5 不实现用户收益排行榜、付费会员或 AI 诊股。
- 不回填上线前无法验证的历史收益，不把当前累计浮盈伪装为历史业绩。
- 不处理现金账户、手续费、税费、分红、送转、复权和券商成交同步；因此收益标记为参考/估算数据。
- 不允许管理员读取持仓数量、成本、总市值、密码、令牌或完整请求体。
- 不改变全市场快照的双来源 Redis 模型和管理员刷新频率权限。

## Decisions

### 1. 收益采用“盘中估算 + 日终固化”的分层模型

- 盘中日收益金额使用 `Σ(quantity × (last - previousClose))`，日收益率使用 `日收益 / Σ(quantity × previousClose)`；分母为零或行情不全时返回明确的数据状态，而不是零值。
- 每个有效交易日收盘后，服务端以统一结算行情源生成 `user_performance_daily`。记录日收益、日收益率、本年累计收益、时间加权本年收益率、年化收益率、数据状态、行情源、统计起始日和计算时间。
- 本年收益率按每日有效收益率连乘；年化收益率按累计净值和自然日折算，少于 30 个有效自然日时返回 `ACCUMULATING`，UI 显示“数据积累中”。金额维度展示“本年收益”，不制造非标准“年化金额”。
- 历史排名必须使用服务端统一结算源，不跟随个人选择的东财、新浪或单股源。

选择该方案是因为它可以在现有持仓模型上提供透明的参考数据，同时避免伪造上线前历史。备选方案“直接按当前成本年化”无法表达收益时间跨度，也极易被修改成本操纵；完整券商级时间加权收益需要交易、现金流和公司行动数据，超出本版本范围。

### 2. 收益聚合与持仓隐私分离

新增 `user_performance_daily`，主键为 `(user_id, trading_date)`，日终任务按该键幂等更新。管理员使用专用聚合 DTO：

- `GET /api/v1/admin/users/{userId}/overview`：用户基础信息、最后登录、持仓证券数量、收益聚合、统计起始日和数据状态。
- `GET /api/v1/admin/users/{userId}/holdings`：仅返回证券代码、名称、市场和行情可用状态。
- `GET /api/v1/me/performance`：返回当前用户首页收益摘要。

管理端接口的查询与序列化层都不得包含 `quantity`、`costPrice`、总市值和单只证券收益金额。相比复用本人持仓接口后在前端隐藏字段，专用 DTO 能在服务端建立真正的隐私边界。

### 3. 普通用户审计使用独立不可变表

新增 `user_operation_audits`，记录 `user_id`、`actor_user_id`、动作、持仓项 ID、证券标识/名称、结果、请求关联 ID 和发生时间。动作至少包括 `PORTFOLIO_CREATED`、`PORTFOLIO_UPDATED`、`PORTFOLIO_DELETED`、`PASSWORD_CHANGED`。不保存数量、成本、密码、令牌、请求正文或响应正文。

管理员通过 `GET /api/v1/admin/users/{userId}/audits?action=&from=&to=&page=&size=` 查询，所有查询强制带路径中的 `userId`，并按发生时间倒序。保留现有 `admin_audits` 用于管理员自身操作，避免改变既有语义。

### 4. 修改密码后撤销会话并重新登录

新增 `POST /api/v1/me/change-password`，请求包含当前密码、新密码和确认值。服务端验证当前密码、现有密码强度策略以及新旧密码不同，使用现有密码编码器保存新哈希，撤销该用户全部刷新令牌并写审计。成功后客户端清除本地会话并返回登录页。

访问令牌在无服务端黑名单的现有架构下可能存活到短期过期时间；本版本不为此引入全局 token 黑名单，但所有刷新会话立即失效。

### 5. 页面采用共享应用壳和显式视图状态

将行情查询、用户偏好、透明小窗同步和全局对话框保留在共享应用壳；首页、我的持仓、行情设置、管理员用户列表/详情作为独立视图。使用单一 `activeView` 状态替代多个 boolean，避免切页时销毁行情轮询。

首页只显示行情源状态、日收益和年度收益摘要；金额/比率分段按钮同时切换对应指标。新增持仓成功后刷新共享 portfolio 查询并跳转到“我的持仓”。我的持仓页面复用现有表格和编辑能力。

选择应用壳而不是把查询放到持仓页，是为了保证首页统计和透明小窗在页面切换后继续刷新。0.1.5 先不引入 URL 路由迁移，减少 Tauri custom protocol 与透明小窗入口的发布风险。

### 6. 移动端采用可达导航和卡片降级

宽度不超过 900px 时提供移动导航（抽屉或底部导航），不得简单隐藏桌面侧栏。页面主体允许纵向滚动，收益卡、行情灯、表格和管理列表在窄屏降级为一到两列卡片；对话框限制在 `100dvh` 内并可内部滚动，输入框与按钮触控高度不少于 44px，并处理 safe-area。

桌面 Tauri 主窗口现有最小宽度保持不变，因此移动规则主要服务浏览器访问，不改变透明小窗布局。

### 7. 单股行情最后成功值按来源永久写入 Redis

为每个单股来源使用独立 Redis Hash，例如 `trading:quotes:akshare:single:{source}`，field 为标准证券 ID，value 为行情 JSON、来源时间和最后成功写入时间，不设置 TTL。成功响应仅 `HSET` 覆盖对应股票；上游失败则返回该来源最后成功值并设置 `stale=true`。只有首次从未成功且缓存不存在时才返回无可用行情。

保留网关短时内存缓存用于请求合并和限流，但 Redis 是跨进程重启的最后值事实来源。不同来源不得共用 field 空间或相互回退，避免来源指示与实际数据不一致。

### 8. 图标从唯一源文件生成

以 `assets/branding/yinxian-app-icon-v1.png` 为唯一源，使用 Tauri 图标生成命令更新 `.icns`、`.ico` 和各尺寸 PNG，并生成 Web favicon。构建前增加配置/资源冒烟检查，避免只替换大图而遗漏 Windows 小图标。

## Risks / Trade-offs

- [当日新增、修改或删除持仓会使盘中日收益与真实成交收益存在偏差] → UI 标记“参考收益”，审计保留变更时间；后续接入不可变交易流水后升级为严格时间加权收益。
- [管理员看到收益金额仍可能推断用户资产规模] → 管理接口只返回聚合值并记录管理访问；上线文案需披露用途，后续可增加更细粒度管理员权限。
- [行情缺失、停牌、零基数导致收益不可计算] → 返回 `PARTIAL`/`UNAVAILABLE` 状态和缺失数量，不用零值掩盖问题。
- [日终结算任务在节假日或行情延迟时错误固化] → 使用 A 股交易日历、Asia/Shanghai 时区、有限重试和幂等键；行情未就绪时保持待计算状态。
- [Redis 永久缓存可能长期陈旧] → 响应携带来源时间、最后成功时间和 `stale`，客户端明确展示最后刷新时间；只更新不主动删除。
- [移动端改动影响桌面紧凑布局] → 媒体查询限定宽度，并分别验证 375×667、390×844、Tauri 主窗口和透明小窗。
- [改密后短期访问令牌仍有效] → 立即撤销全部刷新令牌并缩短现有访问令牌寿命；服务端 token 黑名单留作后续安全增强。

## Migration Plan

1. 通过 Flyway 新迁移创建用户操作审计和每日收益聚合表及索引，不改写现有持仓数据。
2. 部署后端与 AKShare 网关，启用 Redis 单股永久缓存；先验证新接口和缓存降级，再发布客户端。
3. 日终任务从上线后的首个有效交易日开始积累数据，不回填不可验证历史；前端在此期间显示“数据积累中”。
4. 发布使用新图标的 Web 与 0.1.5 桌面安装包，执行数据库迁移、接口、缓存、移动端和双平台构建验证。
5. 回滚应用版本时保留新增表和 Redis key；它们对旧版本无侵入。若禁用日终任务，已生成聚合记录不删除。

## Open Questions

- 产品文案是否接受将“年化收益金额”调整为“本年收益金额”，仅将收益率进行年化；本设计推荐接受，因为年化金额不是标准且容易误导。
- 管理员持仓清单是否允许显示证券代码和名称；本设计默认允许，但不显示数量、成本、总市值或单只收益。
- 用户操作审计的保留期限与管理员查看这些投资偏好数据的隐私告知，需要在正式公开运营前形成政策。
