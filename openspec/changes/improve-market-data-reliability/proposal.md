## Why

当前首页与加自选流程把用户请求、实时行情上游和短期 Redis 快照耦合在一起：上游波动、源配置不匹配或快照过期都会表现为“API 无法连接”或页面长时间卡住。需要把证券基础资料、用户写操作和实时行情解耦，并永久保留最后一次成功行情，以保证非交易时段和上游故障时仍可稳定使用。

## What Changes

- A 股全市场快照仅在北京时间工作日交易时段按配置刷新，非交易时段停止请求上游并继续提供最后一次成功数据。
- Redis 行情快照取消主动过期；刷新仅更新成功返回的证券与快照元数据，失败或空响应不得清空已有数据，也不得回退到 DEMO 行情。
- 新增 PostgreSQL A 股证券目录，保存股票代码、交易所和名称；每天北京时间 08:00 从 AKShare 同步一次，失败时保留既有目录。
- 加自选的搜索和校验改为读取 PostgreSQL 证券目录，保存持仓时不再同步等待实时行情上游；行情缺失不影响其他自选项与首页加载。
- 优化加自选交互：搜索具备加载、错误、超时与竞态保护，提交期间防重复操作；持仓数量和成本使用可编辑文本草稿，允许清空、正确替换初始值并输入小数。
- 首页区分 API 不可达、行情暂不可用和使用最后快照三种状态，避免把行情源故障误报为服务端未启动。
- 首页每只股票显示真实行情的最后刷新时间，陈旧或收盘快照不得用页面轮询时间冒充行情更新时间。

## Capabilities

### New Capabilities

- `security-catalog-management`: 定义 A 股证券代码与名称的 PostgreSQL 目录、每日同步、失败保留和检索行为。
- `portfolio-entry-experience`: 定义自选搜索、保存解耦、输入草稿、超时反馈和防重复提交体验。

### Modified Capabilities

- `market-data-source-management`: 将全市场快照调整为 Redis 永久保留、仅成功增量更新，并明确非交易时段最后快照与部分行情降级行为。
- `portfolio-tracking`: 自选证券从本地证券目录校验，持仓保存不依赖实时行情，单只证券行情缺失不得中断整个列表。

## Impact

- 后端新增证券目录表、Flyway 迁移、目录同步调度器、查询接口及 AKShare 网关目录接口。
- 调整 Redis 快照仓储、交易时段调度、行情聚合与持仓服务的错误隔离；Redis 中现有快照升级后不再设置 TTL。
- 调整桌面/Web 端加自选对话框、API 超时处理、首页状态提示与相关测试。
- 生产部署需要执行数据库迁移并发布 Java API 与 AKShare 网关；桌面端需要构建新版本安装包。
