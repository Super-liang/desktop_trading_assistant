## Context

当前首页以三个高卡片展示收益，切换控件也具有接近主操作按钮的尺寸；持仓页每条记录在桌面端包含多层纵向文本，在移动端则扩展为四行网格。行情状态标签直接使用后端返回的技术名称，出现 `Spring API`、`SNAPSHOT_EASTMONEY` 等英文标识。

本次变更仅调整展示层，必须保持现有行情查询、缓存、持仓编辑与收益计算逻辑不变，并兼容桌面应用、普通浏览器及手机宽度。

## Goals / Non-Goals

**Goals:**

- 在常见桌面窗口内显著降低收益区和每条持仓的高度。
- 让股票名称、代码和最后刷新时间形成清晰的单行身份区，不显示行情源名称。
- 保留价格、涨跌、数量、成本、市值、盈亏、收益率与编辑操作，并以标签化数据单元提升扫读效率。
- 在窄窗口自动换行成紧凑的两列或单列结构，不产生横向滚动。
- 将行情链路名称转换为稳定、可测试的中文文案。

**Non-Goals:**

- 不修改行情数据结构、刷新频率、服务端标签或状态判断逻辑。
- 不改变透明小窗的专用持仓布局。
- 不新增设计依赖或全局组件库。

## Decisions

### 1. 收益区采用紧凑卡片而不是合并成单一文本行

三个收益卡片继续保留独立语义和状态信息，但缩小最小高度、内边距、主数值字号和间距；切换控件使用紧凑分段按钮。这样既能降低纵向占用，也不会牺牲“日收益、本年收益、数据状态”的分组关系。完全合并为一行虽然更矮，但在中窄窗口会造成数值拥挤。

### 2. 持仓记录分为身份行与指标行

每条记录使用一个独立卡片式行容器。身份行将名称、规范化股票代码和最后刷新时间放在同一基线上；指标行在桌面端使用五个等权或按内容分配的指标单元，操作按钮固定在末端。相较继续沿用表头列，本结构允许隐藏冗余表头并减少重复解释文字，同时更容易在移动端降级为两列网格。

股票代码展示去除交易所前缀，只展示用户熟悉的六位代码；完整 `instrumentId` 仍保留在数据和测试中。最后刷新时间仅来自 `sourceTimestamp`，不拼接 `source`。

### 3. 中文行情标签在客户端按组件 ID 映射

前端以组件 `id` 为稳定键映射“后端服务、AKShare 行情服务、东方财富缓存、新浪缓存、东方财富全市场、新浪全市场、东方财富单股、雪球单股”等中文名称，未知 ID 再回退后端 label。相比修改后端接口，这种方式影响面最小，也不会破坏既有客户端契约。

### 4. 保持透明小窗现有 compact 布局

紧凑持仓重排仅作用于普通持仓页；`compact=true` 的透明小窗继续使用现有专用 CSS 网格，避免本次桌面页面优化影响已验证的透明窗口动态缩放。

## Risks / Trade-offs

- [过度压缩导致点击区域偏小] → 编辑与删除按钮仍保持足够的可点击尺寸，收益切换按钮在手机断点恢复不小于 36px 的高度。
- [长股票名称挤压代码和时间] → 身份行允许名称截断，代码与时间保持不换行；极窄宽度下时间换到下一行。
- [后端新增未知状态组件时没有中文] → 保留 label 回退，同时测试现有全部组件 ID 的中文映射。
- [共享 `.quote-row` 样式影响透明小窗] → 使用 `.portfolio-page` 和非 compact 类限定新样式，透明小窗选择器保持更高优先级。
