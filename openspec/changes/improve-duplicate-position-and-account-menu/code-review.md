# 代码审查报告

审查日期：2026-08-09

## 审查结论

未发现阻断级或高优先级问题，可以进入用户本地验收。

## 重点检查

- 用户隔离：重复查询按当前用户过滤；累加按“当前用户 + 持仓 ID”加悲观写锁，越权统一返回未找到。
- 并发一致性：创建先锁当前用户行，累加锁持仓行，避免同用户重复创建竞争和并发追加丢失更新。
- 数值规则：正数数量/成本校验在接口和领域对象两层生效；加权成本按 4 位小数四舍五入；零持仓采用本次成本。
- 数据保留：累加仅更新数量、成本和更新时间，建仓日期、市场、证券、名称与排序不变。
- 审计隐私：累加复用 `PORTFOLIO_UPDATED`，审计参数不含数量和成本。
- 前端契约：仅识别 `POSITION_ALREADY_EXISTS` 时询问；取消不写；确认后调用独立累加接口；普通错误和超时逻辑保持原行为。
- 账户中心：桌面及移动端均有“我的”一级入口，四项账户操作复用原有确认与会话清理逻辑；管理员入口仍可达。

## 审查中修正

- 测试选择器限定到桌面/移动导航和主内容区，避免同名可访问控件造成歧义。
- OpenSpec 并发设计同步为实际的用户行锁串行化方案，消除“捕获约束异常后在回滚事务中查询”的风险。
- 移除已经废弃的移动“更多”样式。
