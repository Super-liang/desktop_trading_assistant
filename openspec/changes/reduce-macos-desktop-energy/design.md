## Context

当前桌面端在 Tauri 配置中静态创建主窗口和透明小窗。登录后主窗口会无条件向隐藏小窗同步会话，使两个 React 应用分别创建 QueryClient 并独立轮询行情。全市场模式的客户端轮询固定为 2 秒，明显快于服务端通常为 30 秒的 Redis 快照刷新频率；窗口隐藏仅调用原生 `hide()`，React Query 不一定能收到浏览器可见性变化，因此后台查询和 WebKit 渲染继续运行。

macOS 性能采样显示，应用本体、两个 WebContent 进程和 WebKit Networking 进程持续高占用，热点包含窗口进程挂起/恢复、JavaScript 微任务和日期本地化格式化。Tauri 在 macOS 使用系统 WKWebView，因此必须同时控制原生窗口生命周期和页面查询生命周期。

## Goals / Non-Goals

**Goals:**

- 未使用透明小窗时不创建第二个 WKWebView。
- 所有定时查询都由原生窗口可见性控制，隐藏状态接近空闲。
- 主窗口和小窗同时显示时只发起一套行情请求。
- 全市场模式匹配服务端快照刷新频率；单股模式保持用户选择的频率。
- 保持老板键、托盘入口、透明小窗动态缩放和会话隔离行为。
- 用自动化测试和 macOS 进程采样证明功能与能耗改善。

**Non-Goals:**

- 不修改 AKShare 网关、Redis 缓存或 Spring API 的行情协议。
- 不引入 WebSocket/SSE，也不改变服务端交易时段调度。
- 不在本次变更中重做页面视觉设计或调整会员功能。

## Decisions

### 1. 透明小窗由 Rust 按需创建

从 `tauri.conf.json` 删除静态 `ticker` 窗口，通过受认证状态保护的 Rust 命令和内部辅助函数创建透明、置顶、无边框窗口。用户点击透明小窗或托盘入口时才创建。小窗主动发出 `ticker-ready`，主窗收到后同步会话，避免创建与页面加载之间的事件竞态。

隐藏小窗时关闭并销毁该窗口，而非仅隐藏。窗口尺寸和位置继续由 window-state 插件保存；重新打开时重新创建 WKWebView。相较长期保留隐藏 WebView，这会增加一次重开成本，但可以确定性释放透明 WebView 的渲染、网络和进程断言负担。

### 2. 建立原生窗口可见性事件

Rust 对主窗口的显示、隐藏、关闭转隐藏、老板键和托盘动作统一发送 `window-visibility-changed` 事件。前端封装可见性 Hook，以原生 `isVisible`/`isMinimized` 初值和事件为事实来源。所有 React Query 使用 `enabled` 绑定可见性；恢复可见后立即失效或刷新关键查询。

不只依赖 `document.visibilityState`，因为 WKWebView 原生隐藏不保证触发与浏览器标签页一致的 visibility 事件。

### 3. 主窗口作为可见时的行情领航者

主窗口可见时正常查询 portfolio，并通过 Tauri 事件把成功结果广播给小窗。小窗监听主窗口可见性和行情广播：

- 主窗口可见：小窗停用自身 portfolio Query，展示主窗口广播的结果。
- 主窗口不可见且小窗存在：小窗启用自身 Query 并按当前模式接管刷新。
- 主窗口重新显示：主窗口恢复查询，小窗收到首个广播后切回共享结果。

这样无需引入跨 WebView 共享内存或新依赖，并保留小窗独立显示的能力。浏览器开发模式没有 Tauri 事件时，各页面保持原有独立查询，便于开发调试。

### 4. 刷新策略与数据新鲜度对齐

`portfolioRefetchInterval` 增加服务端 `refreshSeconds` 参数：

- 全市场快照：使用服务端配置秒数，设置合理的最小值以防异常配置导致忙轮询。
- 单股模式：继续使用用户选择的 2、5、10、20 秒。

查询在重新可见时立即刷新，因此降低后台频率不会导致窗口恢复后继续展示过期状态。行情状态检测由 5 秒调整为 15 秒且仅可见时运行；配置查询维持 30 秒但仅可见时运行。

### 5. 减少无意义渲染工作

日期与时间格式化器提升为模块级单例，避免每条股票、每次轮询重新构造 ICU 格式化对象。行情表使用 memo 化，并在广播数据未变化时避免重复更新。ResizeObserver 只有在缩放值或布局模式实际变化时才更新状态，防止透明窗尺寸反馈循环。

## Risks / Trade-offs

- [小窗重建产生短暂启动延迟] → 小窗先创建空透明页面，通过 ready/session 握手后渲染，并保留尺寸位置以降低感知延迟。
- [主窗口广播与小窗接管之间出现短暂重复请求] → 以主窗口可见性事件先停用小窗 Query，广播只接受带时间戳的最新结果。
- [异常退出导致可见性状态不同步] → 每个窗口启动时主动读取原生状态，事件仅用于后续增量变化。
- [服务端刷新频率异常过小] → 客户端对全市场模式设置最小轮询间隔，不允许形成毫秒级忙循环。
- [跨平台窗口关闭语义差异] → Rust 单元测试覆盖认证和窗口策略，Windows/macOS 都执行前端测试和构建；macOS 额外执行实际进程能耗采样。

## Migration Plan

1. 先发布包含按需小窗和可见性暂停的桌面端，不需要服务端或数据库迁移。
2. 在本地 macOS 验证登录、主窗、小窗、老板键和托盘恢复流程。
3. 对比修复前后可见及隐藏状态下主进程与 WebKit 子进程 CPU/能耗。
4. 验证通过后再构建新的 macOS/Windows 安装包；如出现兼容问题，可回滚桌面安装包，无服务端回滚要求。

## Open Questions

无。当前阶段采用 Tauri 事件协调；未来若增加更多行情窗口，再评估由原生端统一持有行情流。
