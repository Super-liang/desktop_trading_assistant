## ADDED Requirements

### Requirement: 首页与我的持仓分离
系统 SHALL 在首页隐藏持仓明细表，并提供“我的持仓”入口到独立持仓页面；持仓页面 SHALL 保留新增、编辑和删除能力。

#### Scenario: 打开首页
- **WHEN** 已登录用户进入应用首页
- **THEN** 首页不展示证券明细、持仓数量或成本，并显示收益摘要和“我的持仓”入口

#### Scenario: 打开我的持仓
- **WHEN** 用户点击“我的持仓”
- **THEN** 独立页面展示该用户的持仓表及新增、编辑和删除入口

### Requirement: 新增持仓后进入持仓页面
系统 MUST 在新增持仓成功后刷新共享持仓数据并导航到“我的持仓”页面。

#### Scenario: 从首页新增成功
- **WHEN** 用户从首页完成新增持仓
- **THEN** 新增对话框关闭，应用跳转到“我的持仓”且新记录可见

#### Scenario: 新增失败
- **WHEN** 新增请求失败
- **THEN** 应用保留当前页面和已输入内容并显示可理解的错误，不执行错误跳转

### Requirement: 收益金额和比率可切换
首页 SHALL 提供统一的金额/比率分段按钮，并根据选择展示日收益与年度收益的对应指标。

#### Scenario: 切换到金额
- **WHEN** 用户选择“金额”
- **THEN** 首页显示日收益金额和本年收益金额，并使用一致的盈亏颜色规则

#### Scenario: 切换到收益率
- **WHEN** 用户选择“收益率”
- **THEN** 首页显示日收益率、本年收益率和可用时的年化收益率

### Requirement: 页面切换不停止行情与透明小窗同步
共享应用壳 MUST 在首页、我的持仓、行情设置和管理视图切换时维持行情轮询及透明小窗数据广播。

#### Scenario: 切换到我的持仓
- **WHEN** 用户从首页切换到我的持仓页面
- **THEN** 行情查询继续按用户配置频率执行，透明小窗继续收到最新数据

### Requirement: 手机浏览器可完整操作
系统 MUST 在典型手机视口提供可达的导航、纵向滚动、响应式卡片/列表和不溢出的对话框，主要交互目标高度不得小于 44px。

#### Scenario: 375×667 视口
- **WHEN** 用户在 375×667 浏览器视口打开应用
- **THEN** 用户无需横向页面滚动即可访问首页、我的持仓、行情设置、修改密码和退出登录

#### Scenario: 手机打开表单
- **WHEN** 用户在窄屏打开新增持仓或修改密码对话框
- **THEN** 对话框保持在可视高度内、内容可滚动且输入字段采用单列布局

#### Scenario: 手机查看管理用户详情
- **WHEN** 管理员在窄屏查看用户列表或审计记录
- **THEN** 表格内容以卡片或等效响应式结构展示且关键字段和操作均可达
