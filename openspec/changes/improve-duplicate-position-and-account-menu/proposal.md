## Why

当前用户重复添加同一证券时，数据库唯一约束异常被转换成 HTTP 500，既没有说明原因，也迫使用户先手工计算并编辑原持仓。与此同时，修改密码、退出登录、退出全部设备和注销账号散落在首页操作区，挤占核心盯盘空间且账户入口不符合常见 ToC 应用习惯。

## What Changes

- 重复添加同一用户、同一证券的持仓时返回明确的业务冲突，不再暴露为 500。
- 前端收到重复冲突后提示“已存在，是否累加持仓”；用户确认后由后端原子累加到原持仓。
- 累加数量，并按原持仓市值与本次新增市值计算新的加权平均成本；保留原建仓日期，其他用户或其他证券不受影响。
- 用户取消累加时不修改任何持仓；并发重复确认时保证数据库事务和用户隔离。
- 新增“我的”入口和账户中心页面，将修改密码、退出登录、退出全部设备、注销账号统一收纳。
- 首页和持仓页移除上述分散账户按钮，但保留清晰可达的“我的”入口；手机与桌面尺寸均可操作。

## Capabilities

### New Capabilities

- `duplicate-position-merge`: 重复持仓识别、确认与原子累加数量/加权成本。
- `account-center`: “我的”入口、账户操作收纳和危险操作分级展示。

### Modified Capabilities

无。

## Impact

- Spring API：持仓创建冲突响应、累加端点/事务、错误映射与审计日志。
- PostgreSQL：复用现有持仓唯一约束，不新增破坏性迁移。
- Web/桌面前端：添加持仓确认流程、账户中心路由/页面、顶部导航与响应式布局。
- 测试：持仓并发与用户隔离、成本计算、取消确认、账户操作可达性及手机布局。
