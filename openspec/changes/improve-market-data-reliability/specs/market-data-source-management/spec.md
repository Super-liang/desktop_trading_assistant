## MODIFIED Requirements

### Requirement: AKShare 全市场快照模式
系统 SHALL 支持东财 `stock_zh_a_spot_em` 和新浪 `stock_zh_a_spot` 两种全市场快照源，并 SHALL 由后端仅在 A 股交易时段按管理员配置的秒级间隔抓取；Redis SHALL 永久保留最后一次成功快照且每次成功刷新仅更新返回的证券与元数据。

#### Scenario: 东财快照定时刷新
- **WHEN** 模式为全市场快照、源为东财、当前处于交易时段且刷新间隔已到
- **THEN** 后端调用一次东财全市场接口，并在响应非空且完整标准化后更新 Redis 中本次返回的证券和快照元数据且不设置 TTL

#### Scenario: 新浪频率保护
- **WHEN** 管理员选择新浪并设置小于 30 秒的刷新间隔
- **THEN** 系统拒绝配置并说明新浪访问频率限制

#### Scenario: 非交易时段
- **WHEN** 当前不在北京时间工作日 `09:15-11:30` 或 `13:00-15:00`
- **THEN** 调度器不调用全市场上游接口，Redis 快照保持不变且查询继续返回最后一次成功的真实行情

#### Scenario: 快照刷新失败或返回空集
- **WHEN** 当前上游抓取、标准化或 Redis 写入失败，或上游返回空证券集合
- **THEN** 系统保留最后成功的真实快照、记录故障状态且不删除旧字段、不切换到 DEMO 数据

#### Scenario: 刷新结果缺少旧证券
- **WHEN** 一次成功刷新未包含 Redis 中已有的某只证券
- **THEN** 系统不主动删除该证券的最后行情，并由行情时间和证券目录状态标识其时效性

### Requirement: 快照查询只读取 Redis
全市场快照模式下，用户行情查询 SHALL 只从 Redis 最后成功快照读取指定证券，不得由用户请求触发全市场 AKShare 调用；单只证券缺失 SHALL 与其他证券结果隔离。

#### Scenario: 查询已缓存证券
- **WHEN** 用户请求的证券存在于 Redis 最后成功快照
- **THEN** API 返回缓存行情及来源、抓取时间、当前市场阶段和陈旧状态，即使当前处于非交易时段

#### Scenario: 查询集合中部分证券无缓存
- **WHEN** 批量请求中仅部分证券存在于 Redis 快照
- **THEN** API 返回可用证券的行情并为缺失证券返回明确的无行情状态，不因单只缺失而使整个列表失败

#### Scenario: Redis 或完整快照不可用
- **WHEN** Redis 不可连接或尚无任何有效快照
- **THEN** API 返回明确的行情服务不可用错误且不返回 DEMO 行情，健康的 Spring API 不得被描述为未启动

### Requirement: 联通性状态可观测
系统 SHALL 暴露 Spring API、AKShare 网关、Redis 最后快照和当前具体上游的独立状态，并 SHALL 在主页面用指示灯与文字区分连接故障、上游故障和最后快照降级。

#### Scenario: 所有组件正常
- **WHEN** API 与网关可达、所需 Redis 快照可用且当前上游最近调用成功
- **THEN** 主页面分别显示绿色状态及最后成功时间或缓存年龄

#### Scenario: 上游故障但存在最后快照
- **WHEN** 当前上游最近调用失败但 Redis 中存在最后成功快照
- **THEN** 主页面显示上游故障或降级、继续展示标记为陈旧的最后行情，且不提示 API 未启动

#### Scenario: API 不可达
- **WHEN** 桌面端无法连接 Spring API 或请求超时
- **THEN** 主页面明确提示 API 连接失败，并与行情源不可用状态区分

#### Scenario: 单股模式查看 Redis 状态
- **WHEN** 当前模式为单只股票
- **THEN** Redis 快照状态显示为不适用而不是故障
