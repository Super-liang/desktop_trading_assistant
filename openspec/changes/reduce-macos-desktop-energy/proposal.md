## Why

macOS 桌面端在主窗口和透明小窗隐藏后仍持续运行两个 WKWebView，并重复拉取同一份行情，造成高能耗、设备发热以及界面交互卡顿。需要让窗口可见性、行情刷新频率和渲染工作量保持一致，在不牺牲行情时效性的前提下降低空闲资源占用。

## What Changes

- 透明小窗改为用户登录后按需创建，未打开时不启动第二个 WebView。
- 隐藏、关闭或老板键隐藏窗口时暂停该窗口的行情查询；重新显示时立即刷新并恢复轮询。
- 全市场快照模式按照服务端配置的快照刷新频率查询，不再固定每 2 秒重复读取未变化的 Redis 数据。
- 主窗口与透明小窗同时显示时协调行情查询，避免相同偏好下的重复请求。
- 单股模式保留用户选择的 2、5、10、20 秒查询频率，并仅在可见行情窗口中执行。
- 降低行情状态与配置的后台查询频率，并缓存日期格式化器、减少未变化行情的重复渲染。
- 增加窗口生命周期、轮询策略和隐藏恢复行为的自动化测试与 macOS 能耗回归验证。

## Capabilities

### New Capabilities

- `desktop-energy-management`: 规定桌面行情窗口的按需创建、可见性驱动轮询、双窗口协调及空闲能耗行为。

### Modified Capabilities

无。

## Impact

- 影响 `apps/desktop` 的 Tauri 窗口配置与 Rust 窗口命令、React Query 刷新策略、窗口事件同步、行情组件和格式化工具。
- 不改变现有服务端 API、Redis 快照结构、用户行情源偏好及管理员刷新频率权限。
- macOS 为重点验证平台；Windows 继续使用相同的可见性和轮询策略，需通过现有跨平台构建检查。
