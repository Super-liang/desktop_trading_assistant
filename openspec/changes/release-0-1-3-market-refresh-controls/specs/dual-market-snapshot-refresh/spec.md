## ADDED Requirements

### Requirement: 双来源并行刷新
无论服务端默认模式和各客户端当前模式为何，系统 MUST 在 A 股交易时段按照管理员配置的服务端刷新频率并行刷新新浪和东方财富全市场快照。

#### Scenario: 两个来源均正常
- **WHEN** 进入一次到期的交易时段刷新且新浪和东方财富均可访问
- **THEN** 系统在同一轮调度中并行请求两个来源，并分别更新两个来源的 Redis 快照

#### Scenario: 非交易时段
- **WHEN** 调度器运行于非交易时段
- **THEN** 系统不请求任何全市场上游，并继续保留两个来源最后一次成功快照

#### Scenario: 服务端默认模式为单股
- **WHEN** 管理员默认模式为单股且进入一次到期的交易时段刷新
- **THEN** 系统仍并行更新新浪和东方财富快照，使选择全市场模式的普通用户可直接读取缓存

### Requirement: 来源故障隔离
系统 MUST 独立维护每个全市场来源的刷新锁、尝试状态、成功时间和缓存内容；单一来源失败 MUST NOT 中断另一来源刷新或清除任一最后成功快照。

#### Scenario: 新浪失败而东方财富成功
- **WHEN** 同一轮刷新中新浪请求失败且东方财富请求成功
- **THEN** 东方财富缓存和成功状态被更新，新浪保留之前的缓存并记录本次失败

#### Scenario: 同一来源任务尚未完成
- **WHEN** 下一次调度到达时某一来源的上一轮刷新仍持有该来源锁
- **THEN** 系统跳过该来源的重入，同时允许另一来源按自身状态刷新

### Requirement: 分来源永久缓存
新浪和东方财富快照 MUST 写入各自独立且不主动过期的 Redis 数据结构；每次成功刷新 MUST 只更新对应来源的数据。

#### Scenario: 刷新新浪快照
- **WHEN** 新浪全市场快照成功返回
- **THEN** 系统原子更新新浪缓存且不改变东方财富缓存，并且不为行情数据设置主动失效时间

### Requirement: 服务端刷新频率权限与展示
只有管理员 MUST 能修改服务端全市场快照刷新频率，该频率 MUST 同时作用于新浪和东方财富；全市场模式首页 MUST 显示“服务端快照刷新频率”及当前秒数。

#### Scenario: 普通用户查看全市场模式
- **WHEN** 普通用户打开全市场模式首页或行情配置页
- **THEN** 用户可以看到当前服务端刷新频率，但不能提交该配置的修改

#### Scenario: 普通用户切换工作模式
- **WHEN** 普通用户在全市场和单股模式间切换并保存本机设置
- **THEN** 服务端刷新频率保持不变，普通用户请求不得包含修改刷新频率的写操作

#### Scenario: 管理员修改刷新频率
- **WHEN** 管理员提交合法的服务端刷新秒数
- **THEN** 后续新浪和东方财富调度均采用新频率，首页展示同步更新
