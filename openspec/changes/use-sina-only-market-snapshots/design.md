## Context

当前全市场快照调度同时包含 A 股东财/新浪、港股东财、美股东财/新浪。生产环境中东财 `push2.eastmoney.com` 对腾讯云公网 IP 持续主动断开连接；同时 AKShare 新版东财全市场接口采用多页串行抓取，无法稳定满足现有 30 秒截止时间。新浪 A 股快照已经在线上成功写入 Redis，因此本次将全市场快照收敛为单一新浪线路。

系统仍需兼容数据库中已经保存的 `EASTMONEY` 配置、客户端 localStorage 中的旧偏好和 Redis 中的旧东财键，不能通过破坏性数据迁移完成切换。

## Goals / Non-Goals

**Goals:**

- A 股、港股全市场快照只调度和读取新浪来源；美股只刷新系统中用户持仓/自选证券的新浪行情。
- 为 AKShare 网关增加港股新浪快照适配，并保持既有标准化行情结构。
- 旧的东财全市场配置在服务端和客户端都自动归一化为新浪。
- 全市场刷新失败时继续保留 Redis 中最后一次成功的新浪行情，且不设置主动过期时间。
- 开盘基线采集跟随新浪成功快照执行。
- 页面、能力列表和联通检测不再展示东财全市场线路。

**Non-Goals:**

- 不移除东财单股行情、证券目录、基金净值等非全市场能力。
- 不引入新的商业行情供应商。
- 不修改各市场交易日历和交易时段定义。
- 不删除历史东财 Redis 键或数据库枚举值。

## Decisions

### 1. 调度路由使用显式的新浪白名单

`MarketSnapshotScheduler` 只保留 `A_SHARE/SINA`、`HK_STOCK/SINA` 两条全市场路由。美股由独立持仓行情任务在交易时段读取数据库中的去重证券标识，批量请求新浪简单行情接口并增量写入 `US_STOCK/SINA` Redis 快照。相比“保留东财但设置为备用”，该设计确保生产环境不再访问东财节点，也避免 AKShare 新浪美股 896 页全量抓取。

### 2. 保留枚举值，通过边界归一化兼容旧数据

暂不删除 Java/TypeScript 中 `EASTMONEY` 枚举，因为数据库历史记录、旧客户端请求和其他非全市场能力仍可能引用该字符串。服务端读取或接收全市场来源时统一映射为 `SINA`；客户端初始化旧偏好时也写回 `SINA`。相比直接修改数据库字段或删除枚举，此方案可滚动部署并兼容尚未升级的客户端。

### 3. 港股使用 AKShare `stock_hk_spot()`

网关把 `HK_STOCK/SINA` 映射到 AKShare 新浪港股全市场接口，并新增字段契约与规范化逻辑。港股代码统一为五位并生成 `HKEX:<code>`；最新价、今开、昨收、涨跌额、涨跌幅和时间戳映射到现有 `Quote` 契约。

由于新浪港股接口也采用分页请求，网关继续使用隔离子进程和硬截止时间。本地实测 A 股约 16.6 秒；腾讯云实测港股约 3.8 秒，但 A 股在 30 秒边界内未完成，因此生产环境将上游硬截止设置为 50 秒，并保留 Java 客户端 60 秒总边界。AKShare 新浪美股接口固定每页 20 条、约 896 页，无法满足该边界，必须采用持仓集合批量策略。

### 4. Redis 按市场和新浪来源隔离，成功后原子更新

继续使用 `trading:quotes:akshare:<market>:snapshot:sina` 键。A 股、港股只有完整抓取并通过契约校验后才更新；美股只覆盖本轮成功返回的持仓/自选证券字段，并保留其他证券最后成功值。失败时不清空、不设置 TTL。历史东财键保留用于回滚，但业务读取不再选择它们。

### 5. 美股新浪采用持仓集合批量接口

网关新增只接受规范化 `NASDAQ/NYSE/AMEX:<symbol>` 列表的美股新浪批量行情端点，内部按安全批量大小拆分请求，并将代码、价格、昨收、开高低、涨跌、成交量和来源时间转换为标准 `Quote`。请求和日志不得包含用户身份、数量或成本；Java 调度只传去重后的证券标识。单轮失败不得覆盖 Redis，且任务仅在美股交易时段执行。

### 6. 收益基线和持仓读取统一跟随新浪

开盘基线的触发条件由“东财成功”改为“新浪成功”。跨市场收益查询和持仓行情查询必须按各自市场读取新浪快照，不能继续对港股硬编码东财，也不能过滤掉港股、美股证券。

### 7. UI 不再提供无意义的全市场来源选择

全市场模式展示固定来源“新浪”，不提供东财选项；管理员仍只能配置服务端刷新秒数。单股模式的来源选择保持原样。能力/联通状态只展示 A 股、港股新浪快照和美股新浪持仓行情，防止用户把已移除线路误认为可切换来源。

## Risks / Trade-offs

- [新浪成为单点来源] → Redis 永久保留最后成功数据，并通过每市场最后成功时间和陈旧状态明确降级；后续新增来源时再恢复多源策略。
- [美股批量接口属于新浪公开网页行情且无 SLA] → 使用严格输入校验、请求超时、Redis 最后成功数据和来源状态降级；后续商业化前替换为授权行情源。
- [全体用户美股标的集合增长] → 去重后分批请求并设置单轮上限，超限时分轮更新，避免 URL 过长和突发流量。
- [旧客户端仍提交 EASTMONEY] → API 接收后归一化为 SINA，不返回错误导致旧客户端不可用。
- [新浪字段变化] → 在网关增加字段契约测试，字段缺失时拒绝覆盖 Redis 的最后成功快照。
- [回滚需要东财路径] → 保留枚举、适配代码和历史 Redis 键；回滚调度路由即可恢复，不执行数据删除。

## Migration Plan

1. 先部署 AKShare 网关的港股新浪适配和能力声明，并验证三个市场新浪接口。
2. 部署 Java API，将旧配置归一化为新浪、切换调度/读取/基线路由。
3. 部署 Web 前端，移除东财全市场选项并迁移本地偏好。
4. 检查三个新浪 Redis 键的 `__metadata__`、数量与 TTL，确认失败时旧数据保持。
5. 观察至少一个对应市场交易时段内的成功/失败日志和最后成功时间。

回滚时恢复上一版本应用和网关；由于未删除数据库配置和历史 Redis 键，不需要数据恢复。

无；用户已确认美股采用持仓/自选证券按需刷新方案。
