## ADDED Requirements

### Requirement: 单股最后成功行情永久保留
系统 MUST 按单股行情来源和证券标识在 Redis 保存最后一次成功行情，且不得为这些数据设置主动过期时间。

#### Scenario: 上游请求成功
- **WHEN** 指定来源返回某证券的有效最新行情
- **THEN** 系统只更新该来源、该证券的缓存值及最后成功时间，不清空其他证券或来源

#### Scenario: 服务重启
- **WHEN** AKShare 网关或 API 服务重启且 Redis 数据仍存在
- **THEN** 系统仍可读取重启前最后一次成功行情

### Requirement: 刷新间隔内持续返回最后数据
系统 SHALL 在客户端轮询间隔和上游失败期间持续返回最后成功行情；返回历史值时 MUST 标记为陈旧并携带原始行情时间和最后成功时间。

#### Scenario: 上游临时失败
- **WHEN** 某证券本次实时查询失败但对应来源已有缓存
- **THEN** 接口返回缓存行情且 `stale=true`，客户端不把该证券行清空

#### Scenario: 首次无任何成功数据
- **WHEN** 上游查询失败且该来源、该证券从未产生缓存
- **THEN** 系统返回明确的无可用行情状态，而不是伪造价格

### Requirement: 不同单股来源相互隔离
系统 MUST 分别存储和读取每个单股来源的数据，不得使用另一来源的数据冒充用户当前选择的来源。

#### Scenario: 选中来源不可用
- **WHEN** 用户选中的来源失败而另一来源存在新数据
- **THEN** 系统只返回所选来源自身的最后成功值，并保持来源标识一致
